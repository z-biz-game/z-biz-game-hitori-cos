「枯竭 N 次」不是形容词：N 是 js/core/solve.js 在这一盘的题面上，纯推理走到走不动、 不得不假设一次的次数。0 次就是全程不用猜。40 盘的解数每盘都由 js/core/brute.js 的第二套独立代码逐格复核过（4×4 是全部 65,536 个子集），两套说不同就不发布。

  1. 每行每列不得出现两个相等的未涂数字
  2. 任意两个涂黑格不得正交相邻
  3. 所有未涂格正交连通
这一盘的数字从哪来

屏幕上每个数都是从盘面读出来的，不是估的：黑数 / 打点 / 未定 / 冲突 / 连通 全部出自 rules.audit()，最佳 是 game.minTaps(lot)——「一个黑格一下、一个点两下」的地板价， 由该盘自己黑几个格子算出。冲突三色各自对应上面那条编号的规则：一条规则一个颜色，不共用。

点「提示这一格」时，页面跑的是 js/core/solve.js 里那条不回溯的铅笔路 （facts() + propagate()）在你当前盘面上的下一步：它说得出这一格是被 哪一条规则逼住的。它从不读 js/data/lots.js 里烘焙的答案，也不会替你把假设往下推—— 推理枯竭之后要做的那个假设，永远留给你。

题库来自 tools/bake.mjs：构建期跑生成器 js/core/make.js，只收下三条独立复核都点头的盘面—— 生成器自己的完整枚举报 solutionCount === 1；把序列化之后的这一盘重解一遍， solutionCount / depth / guesses 三个数字必须一字不差地复现；最后由另一套写法的 brute.js 独立再核一次——4×4 的两档是全枚举（65536 个格子子集），5×5 与 6×6 是 抽样（每盘 2 万+ 子集），mode 与 subsets 就记在每一盘的数据行上，不藏着。 浏览器不生成、不搜索、不回溯：make.js 与 brute.js 不被任何页面文件 import。 进度与纪录只存在这台设备的浏览器里。
